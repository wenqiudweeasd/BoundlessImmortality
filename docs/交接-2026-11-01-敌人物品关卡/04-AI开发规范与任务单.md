## 1. 任务边界与开工

只开发本地敌人、物品、宝箱、装备法宝及测试关卡。**不要求接手者学习、开发或测试抖音互动；不修改 SDK、平台 Provider、评论命令、礼物、回执或正式支付。** 三把剑使用本地测试生成接口。不要以“需要先联调平台”为这些模块的前置条件。

开工读本交接包、`CONTRIBUTING.md`、实际存在的 AGENTS.md 和相关源码。记录分支/提交/工作区、stash/worktree/LFS；保护已有资产、存档与未提交文件。当前基准 a486e36 可能变化，以实际为准。新代码可建 `codex/goblin-dungeon` 分支；不得自动清理其他人的未跟踪设计目录。

```powershell

git log -1 --oneline
git stash list
git worktree list

```

只在新本地测试档操作，建议使用独立 `Saved/GoblinDungeonTest`，路径隔离是需要实现的配置，不宣称已有。已有 `Saved/XianTu` 与 `Saved/CultivationPrototype` 在会被测试修改前先备份。临时调整敌人属性和强制掉落不能写回默认正式数据。

## 2. C++ / Blueprint 边界

| C++ 负责可信规则 | Blueprint / 资产负责展示与拼装 |
|---|---|
| 怪物配置读取、成长与伤害接口、共享血池、技能资格/CD、召唤集合、死亡一次性出口 | 五种派生BP、骨骼组件、动画蓝图、装甲材质、水晶首领与分身视觉 |
| 物品 ID/实例、概率与种子、货币、拾取提交、材料永久来源、装备套装数值 | 开箱动画、物品抛出/光柱、交互提示、血条、小地图 |
| 房间图与状态、门锁判定、本局重置、测试命令保护 | 房间白盒、上下左右门位、生成点、特效和声音 |

用 `USTRUCT(BlueprintType)` 配置行/DataAsset/DataTable 暴露 ID、境界、基础属性、速度系数、掉落池与资源软引用。建议集中数据表，不在5个蓝图复制成长算式。每个参数注明单位：cm、s、0–1概率、百分点/归一化比率。规则定在 C++，Blueprint 通过只读快照和事件展示，不直接写共享HP/钱包。

建议新增类/目录仅是计划，当前尚不存在：`Gameplay/Enemies/`、`Gameplay/Loot/`、`Gameplay/Dungeon/`，以及 `/Game/Gameplay/GoblinDungeon/{Enemies,UI,Items,Rooms,Maps}`。敌人C++子类继承 `ALiveMonster`；五种BP可复用一个基类，通过配置选择美术与数值，首领使用专门子类。

### 接口接入的关键注意事项

- 现有特殊剑 `ALiveSpecialSword::DealDamage` 直接调用 `ALiveMonster::ApplyHit`，该函数当前不是 virtual；仅覆写 `ApplyWeaponHit` 不足以接管首领共享受伤。应在基类统一伤害入口提供最小虚函数/组件转发，保留现有击杀归属。`Devour` 同样不是 virtual，且直接扣 `Health`、调用 `FinishDamage`，绕过 `ApplyHit`；必须单独接管/转发吞噬终结路径，不能以为改了 ApplyHit 就全部完成。
- 血条与目标可攻击性也必须读取共享状态：当前 `IsAlive/GetHealthFraction/GetCurrentMaxHealth` 等并非可覆写接口，只在派生类隐藏同名函数不影响基类指针调用。通过基类访问器委托共享组件或最小虚接口统一，不能让注册表、剑灵和HUD分别看到三种生命状态。
- `ApplyPush` 目前只修改基础敌人的私有推力状态。派生怪不要再在另一套 Tick 中硬设位置而抵消推力；若引入 CharacterMovement，必须提供兼容桥接并跑原剑灵测试，不假定 LaunchCharacter 自动生效。
- `LiveMonsterRegistrySubsystem` 注册的仍需是可查询敌人，分身参与目标选择但不重复经济结算；EndPlay解绑，弱引用清理召唤集合。
- 首领共享血池不能靠每帧 `Other.Health=This.Health` 实现；两次同帧命中、死亡回调与多段伤害会错。使用共享状态的统一提交。
- `XianTuSubsystem::GetState/Execute` 等主要是 C++接口；需要蓝图调用时补薄层，不凭空写不存在节点。现有 `TryGear` 仅试穿，不能直接复用其提示就声称属性生效。
- 筑基材料需要具体身份与永久属性来源；旧 `MaterialKey(stage,category,grade)` 不够，不混成同一个物品。新测试规则和旧存档的兼容要明确，禁止重命名旧ID或用删存档解决。
- `.uasset/.umap` 为二进制，只由一个人编辑同一资产。AI没有编辑器工具时交节点步骤和参数，由程序员实际保存与运行；不谎报创建完成。

## 3. 14 小时首周最小交付

首周是完整需求的第一阶段，不含完整 BOSS 三技能、全材料永久属性与套装系统。目标：普通敌人模块→实际受击/击退/血条→一次掉落拾取→四向白盒入口。首领配置可以生成供后续使用，但不计技能完成。

| 日 | 约2小时任务 | 验收输出 |
|---|---|---|
| D1 | 0.5h阅读/基线；0.5h构建与旧怪烟测；1h配置结构与成长函数 | 五行怪物配置、境界索引和数值单元测试；BOSS配置仅静态面板 |
| D2 | 1h普通怪派生与骨骼/材质连接；1h追踪、攻间隔与碰撞 | 四类普通怪正确生成、移动/攻击；首领暂用占位外观 |
| D3 | 1h沿用/扩展血条；1h三把剑本地命中与击退验证，补驱煞大招击退 | 不脱离现有伤害/注册表，无重叠血条、不穿墙 |
| D4 | 1h最小物品定义/掉落堆；1h普通怪死亡一次性掉灵玉与E拾取 | 不直接进钱包；重复死亡/拾取不重复入账 |
| D5 | 2h新建S、H及上下左右测试房白盒与成对门触发 | 至少中心四向可通、可返回；不要求九房全部有内容 |
| D6 | 1h本房清怪开门/回房不重刷；1h关键测试修复 | 普通怪战斗→开门→拾取→岔路流程可演示 |
| D7 | 1h集成风险缓冲；1h记录和交接 | C++构建、PIE证据、资产清单、下周待办和已知问题 |

首日发现现有构建/动画绑定阻塞应当日说明，先用简单可区分占位模型完成规则；不能整周调材质却没有战斗闭环。若进度落后，优先保留普通怪成长、伤害和碰撞正确性，减少房间内容/特效，不牺牲基础验证去声称全部完成。

## 5. 测试与交付规范

本地测试维度：

| 领域 | 必测边界 |
|---|---|
| 属性 | r0/4/6/8/9，g改变仍正确，装甲加值顺序，成长不重复叠加 |
| 伤害/击退 | 三剑命中每类，墙边、中心重合、连续击退、击退中死亡；原有普通怪不回归 |
| 首领 | 等于50%/略低50%/直接致死，分身不递归；两身体同攻击段与不同伤害段；共享死亡只一个箱 |
| 技能 | 留1召唤物不再召，CD/全死组合；5s/300cm预警命中；友军击杀只吸收一次且无生命增长 |
| 概率 | 固定seed可复现；强制0%不出/100%必出；十池全中/全不出合法；各档独立而非权重；首领及其宝箱配置不得引用三种元婴吉兆，即使强制全中也不能产出 |
| 拾取 | 连续E、满包、提交失败、切房返回、关卡重置；数量和钱包只加一次 |
| 材料 | 首领其他材料只BR01、沿用确定突破；三种吉兆仅BR04（21→22）可选，概率加值正确且每轮不重复累加、成功消耗/失败保留、不永久增加概率；其余材料成功消耗并永久生效、加载不重加、旧物品兼容 |
| 装备 | 同槽替换、2/4套装升降、重复穿脱、冷却切换、减伤/会心上限 |
| 房间 | 双向门、锁门、跨房清怪隔离、回路不重刷、角色死亡和离开未拾取确认 |

不为每个UI颜色写测试，优先规则与状态边界。概率用固定流和数据校验验证，不能要求靠实际刷一百次就“证明1%”。源码审查、C++编译、自动化、PIE手工、打包运行分开记录；首周不要求平台测试。相关既有测试位于 `LiveWeapons/Tests/LiveMonsterTests.cpp`、`Combat/Tests/LiveCombatTests.cpp`，先读实际测试名再运行，不能捏造测试数量。

交付物：本次源码/配置清单、BP与地图绝对/包路径、节点连接说明、实际构建命令与结果、PIE操作步骤及截图/短视频、逐项完成/未完成表、总工时和下一包入口。只提交本任务相关文件，不提交Saved、构建缓存、旧存档；资产按LFS规则处理。
