# 一周策划：同心护劫 · 免费直播互动闭环

> **本任务单已撤销，不再让接手者执行直播互动开发或测试。** 当前一周安排见 [敌人物品关卡任务单](../交接-2026-11-01-敌人物品关卡/04-AI开发规范与任务单.md)。以下仅作历史保留。

## 交接目标

另一位程序员使用 AI 辅助，以 C++ 加 Blueprint 开发，每天约 2 小时，七天合计 14 小时。本周从已有的加入与渡劫助力出发，补齐可靠接收、归属判断、反馈和回执，形成一次能现场演示的免费互动体验。已有商城、突破和剑灵体系继续复用。

本方案是建议派工范围，不是平台上线承诺。估时假设接手人熟悉 UE C++、本机 UE 5.8 可用、工程能构建；首日若基线构建失败，先记录并重排，不把修环境时间藏进“已完成”。

考虑过三个方向：先补装备/外观更容易看见新内容，但不能解决直播接入；直接补正式后端与付费闭环依赖多，超过本周容量；推荐先完成免费评论互动的业务闭环，并做有条件的真实联调。后两阶段功能保留在缺口清单 B01–B13，由同一程序员继续拆单承接。

## 体验流程

主播进入已有玩法 → 观众发送“加入”获得/恢复自己的剑灵 → 主播按现有条件发起渡劫 → 15 秒准备期显示操作引导 → 60 秒渡劫期观众发送“助力” → 剑灵出现护卫表现，HUD 更新有效助力与概率 → 揭晓结果 → 保持原有失败/成功处理。

主界面复用当前渡劫页和 HUD；不增加独立活动大厅。中文预设反馈可以公开展示；不把观众原始评论直接转发到画面。[准入规则](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/introduction/live-play/creation)

## 互动规则与边界

| 条件 | 本周策划行为 | 数据影响 |
|---|---|---|
| 新观众精确发送“加入” | 复用已有加入路由与反馈；重复加入恢复/更新同一身份 | 不重复生成同一观众 |
| 已有观众发送 1–4 | 保持当前切换规则 | 不引入新武器权益 |
| 准备期发送助力 | “天劫尚未开始，稍后再助力” | 不占本次助力资格 |
| 渡劫期首次助力 | “助力已收到”，已有剑灵申请护卫表现；更新人数/概率 | 当前房间、当前 AttemptId、该用户仅一次 |
| 未加入者首次助力 | 为保持现有语义，允许合法观众计入；不自动增加一把剑，提示可发送“加入” | 有效身份仍只计一次；无剑灵则仅显示预设反馈 |
| 同用户不同消息再次助力 | “本次已助力”短反馈，聚合显示避免刷屏 | 不重复增加 |
| 超过 50 名 | 继续确认收到，既有剑灵护卫照常；显示“概率助力已达上限” | 助力集合可记录更多人，公式只取前 50 名；不要误改成第 51 人无任何反馈 |
| 渡劫已结束/揭晓中 | “本次助力已结束” | 不修改冻结结果 |
| 主播自己、空身份、旧房/旧代次事件 | 拒绝影响本次助力，必要时仅开发日志记录原因 | 不加概率；不因拒绝伪造成功履约 |

命令匹配：当前代码 `Content.Contains("助力")`，本周保持兼容，不无声改成精确匹配。控制台配置的指令词及实际推送范围需一致核对；未收到某条评论时先查平台是否推送，不能直接认定解析错误。下一版本如要收紧匹配，单独更新策划、平台配置和回归用例。

概率沿用源码，单位为万分比：

```text
P = clamp(5000 + min(助力人数, 50) × 100
          + min(同境界历史失败次数 × 1000, 5000)
          - FortunePenalty(), 0, 10000)
```

即基线 50%，每名不同观众提供 1 个百分点，概率助力最多贡献 50 个百分点；失败保护与当日签运罚值仍生效，不承诺 50 人一定达到 100%。展示来自真实结果，不另算一份蓝图概率。

会话建议：开始本轮时绑定平台、应用、房间、主播和 AttemptId，短断保留已计用户但拒绝旧代次事件；新代次只有匹配原业务上下文才恢复接收。跨房/跨应用/切换模式不能把当前渡劫或未展示结果带进新上下文。平台可能主动切房，不能仅靠禁止界面按钮保证安全。

失配后的建议安全默认：保留原轮与资源预留记录，暂停该轮推进及经济结算，不向新房扣发或发送旧消息回执；显示“原直播会话中断”。只有原房原主播及原 AttemptId 可确认匹配时恢复。当前已开始 Trial 的风险不能用普通 Cancel 消除（`XianTuSubsystem.cpp` 的 `TribCancel` 分支），不得删档、直接清空 Trib 或换房发奖。无法恢复原上下文或需要超时处置时，记录为阻塞，由维护人提供可验证的恢复方案，不自动取消风险。若暂停与恢复牵涉超出本周容量的账本改造，交付本地修复版并禁止启用正式渡劫接入，不能宣告完整重连能力。这些是本次建议规则，实施前需逐项核对现有状态机与预留语义。

## 验收矩阵

| 用例 | 输入与观察 | 通过条件 |
|---|---|---|
| A01 加入与切换 | 新人加入两次，再发 1–4；未加入者发数字 | 身份不重复，保持原有切换限制 |
| A02 时间窗口 | 准备/Trial/冻结/结束分别发助力 | 仅 Trial 首次有效助力改变状态，其他有预设反馈 |
| A03 用户与消息重复 | 同用户发两条；同 MessageId 重投；不同用户各发一次 | 用户资格和消息幂等各自正确，概率不重复增加 |
| A04 上限与签运 | 49/50/51 名；存在失败保护、FortunePenalty 的组合 | 按源码公式，51 名仍有反馈，不突破上下限 |
| A05 非法来源 | 空身份、旧会话、另一房、主播自身 | 当前助力集合、概率、冻结结果均不变化 |
| A06 重连与切房 | 同房断线重连；渡劫中换房；下一次渡劫再次助力 | 同一轮同用户不重计；失配时旧轮不推进/结算到新房，预留不被无损取消；仅匹配原上下文恢复；下一轮资格重置 |
| A07 ACK 边界 | 已处理未展示、旧 HUD 正在绘制而本条助力反馈未显示、展示后、异步失败、重投、消费方未就绪、队列满 | 按本条 MessageId/结果版本确认展示，未展示不提前报成功，失败可观察且不伪报履约；重试不重做业务；具体 SDK 成功层次如实标注 |
| A08 蓝图生命周期 | 重开两次 PIE、重进场景、关闭/打开页面 | 一次事件只触发一次表现，无失效引用和重复绑定 |
| A09 模式隔离 | 本地 GM 与平台测试分别运行 | 状态标识准确，不静默把平台失败退回模拟；不使用付费礼物完成本周测试 |
| A10 可选真实链路 | 官方测试主播启动包，调试成员发加入/助力 | 记录 SDK 接收、UE 判定、可见表现与回执链，敏感值打码；缺条件填未测 |

A01–A09 是本周目标，A10 有条件执行。静态审查不能替代这张表。断网、回执失败、跨会话等可以由开发测试 Provider 注入；报告必须注明注入条件，不把注入证明当作平台网络实测。

## 缩减与风险处理

优先级顺序：来源与状态归属 → 不重复计入 → 最小预设反馈 → 展示后回执 → 蓝图额外光效 → 真实联调。落后时先删新增特效，使用现有通知，不删身份检查或必要验证。到 D4 尚未建立可靠状态归属，应把目标调整为“免费本地修复版”，登记剩余任务，不能勉强开放正式礼物。

D1 基线构建或第三方材料缺失：只交事实与阻塞，继续能够独立验证的代码定位/测试。出现账本迁移、跨崩溃付费重放或整套宿主重建，转 B01/B02/B03，不挤进本周。14 小时是有条件估算，允许交付明确未完成项，不允许把它们勾为通过。
