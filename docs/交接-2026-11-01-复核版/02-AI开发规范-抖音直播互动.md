## 2. 怎样接入抖音直播互动

### 2.1 确认产品与权限

本项目目标按“直播小玩法”检查，不套用抖音小游戏、直播伴侣互动工具或第三方 App 的接口。负责人通过平台核对：AppID、有效提案、评论等所需能力、SDK 工具权限、测试主播、调试成员、有效启动方式。程序员输出表格，每项填“已具备/待提供/未核实”、证据日期和维护人。[创建直播玩法](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/introduction/zn/toybox-start)

### 2.2 选择接入方式并核对现有桥接

官方 SDK 提供指令直推与抖音云接入等能力。考虑当前 UE 工程已有进程桥接，本周建议复用 Unity 官方 SDK 宿主 → UE Provider，而不是另写协议抓取直播数据。SDK 通过 BGDT 获取，使用其公共 API，不修改内部 Runtime 层；旧 README 提到的 2.7.12 不能作为当前已安装版本证据，需查实际包清单。[SDK 概览](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/develop/unity-sdk/overview)、[Unity SDK 接入](https://partner.open-douyin.com/docs/resource/zh-CN/interaction/develop/unity-sdk/unity-sdk-access)

当前依赖核对：

| 项目 | 本机情况 | 接手动作 |
|---|---|---|
| `LiveInteraction`、`DouyinLiveProvider` | `.uproject` 已启用 | 追踪真实运行模式，不以插件启用等同联网 |
| SDK 宿主 | `Plugins/DouyinLiveProvider/Binaries/Win64/SdkHost` 有运行文件 | 记录版本/来源与完整依赖，核对干净克隆如何获得 |
| `Tools/DouyinSdkHost`、`Tools/DouyinLauncher` | 当前目录未找到 | 向维护人取得工程或准确仓库位置；不得假造编译脚本 |
| AppID | 当前默认配置未见对应配置段 | 从本项目控制台核实后配置；不复用别的项目身份 |
| 礼物映射 | 当前配置八种，README 混有另一项目五种礼物与阵营 | 本周不修改权益；后续逐项对照本项目官方配置 |

### 2.3 沿现有路径完成一条事件

```text
官方启动与授权
  → Unity SDK 宿主接收平台消息
  → GWSDK/1 内部帧 / DouyinLiveProvider（不是官方消息协议）
  → ULiveInteractionSubsystem（当前会话、来源、事件分发）
  → C++ 游戏业务（加入 / 切换 / 助力）
  → Slate 或 Blueprint 表现
  → 展示完成后的履约提交 / 异步结果与重试
```

Provider 已读取 `-GWCredentialStdin` 的一次性 stdin 凭证，再经管道传给宿主。不要把真实 token 放进编辑器命令行、配置、日志或截图；没有可用的安全启动器就记为阻塞。AppSecret 属于服务端。不要尝试用原生 DLL 猜测 Unity SDK 的 C ABI。

事件业务至少校验当前会话、非空作用域身份与消息标识；身份使用 `GetScopedUserId`，不要用昵称作主键。平台、应用、房间、主播、代次/nonce 和测试模式按现有底座契约一致，断线后旧事件不能写入当前业务。SDK 回调进入 UE 后，UObject/UI 与游戏状态更新应在游戏线程执行。

### 2.4 履约与重复消息

三件事分别验证：消息 ID 去重、同一用户本次渡劫只助力一次、ACK 失败重试。`Deliver* == true` 只表示分发，不能代替业务成功或已渲染。当前适配器的 `NotifyPresented` 来自既有 HUD/GM 绘制，**不能直接证明仙途助力反馈已经显示**。可复用队列与重试，但需用 MessageId 或结果版本关联助力表现与展示确认，确认后才允许该消息进入可提交状态；不能新增“每条评论无条件 ACK”。正式履约应在效果正确展示后上报，按实际 SDK 公共接口契约调用。[指令直推能力](https://partner.open-douyin.com/docs/resource/zh-CN/interaction/develop/unity-sdk/live-unity-sdk-support/direct-push-ability)

接手时建议保留两个业务订阅入口，提取小型助力处理结果并连接现有回执队列，避免在 14 小时内重构全项目事件总线。也可由接手人选择单路由，但必须说明如何保持竞采、武灵评论与 1–4 切换不退化。同一消息只有一个履约所有者；结果枚举可设计为 Applied、AlreadyApplied、Inactive、Invalid，不把业务枚举直接当官方 ACK 错误码。

普通无关评论不计成功；同消息重投不重演经济/概率变化。对已处理消息如何重新提交 ACK，要保留处理结果，按当前 SDK 契约处理。相同用户发送不同助力消息属于业务重复，不等同网络重投，给出预设反馈，不再次加概率。必须测试“旧 HUD 仍在绘制，但助力通知尚未显示”的情形，不能提前提交该助力消息。NullRHI 测试不能证明展示履约。

### 2.5 平台测试与发布

先用独立的本地模拟身份验证，再使用官方自测工具；具备开播权限后，由负责人操作测试主播在直播伴侣启动测试包，调试成员发送指令。官方 mock 也不是本地 GM；真实直播评论又是单独一层证据。不得把官方自测数据导入生产权益。测试送礼可能发生真实费用，本周免费链路不需要程序员或 AI 自行送礼。[测试与提审](https://developer.open-douyin.com/docs/resource/zh-CN/interaction/introduction/zn/test%26arraignment)

本周不解除 `HandleGift` 的平台测试礼物隔离。现有实现与 README 对测试履约的描述有差异，后续 B03 应按实际 SDK 文档，在隔离环境补齐；不能通过屏蔽 ACK 或直接污染正式存档解决。生产礼物还需持久事件账本、原子业务处理、崩溃恢复及补偿，4096 条内存去重不满足该目标。

## 3. C++ 与 Blueprint 分工

| C++ 必须拥有 | Blueprint 适合承担 |
|---|---|
| 会话/身份检查、命令解析、助力状态、概率、去重、ACK 归属与重试 | 现成 Niagara 特效触发、轻量音效和动画、表现参数配置 |
| 存档格式与状态恢复；连接状态的可信来源 | C++ 结果到展示的连接；开发场景内模拟按钮 |
| 只读展示数据与生命周期通知 | 不含凭证的调试面板、预设反馈样式 |

当前 `UXianTuSubsystem` 的 `Execute/GetState/TakeNotices` 是 C++ 接口，不要声称蓝图已可直接调用；当前 UI 是 Slate，已有 `UInkGameUIWidget::ShowToast/OpenRoute` 为 BlueprintCallable。优先用现有通知展示文字。确需蓝图事件时，新增最小 `BlueprintType USTRUCT` 结果及 `BlueprintAssignable` 委托，或一个薄组件桥接；这是拟新增接口，命名由接手人决定，不能让蓝图直接写内部账本。

事件结果只暴露表现所需的状态、昵称展示值、当前概率和有效人数等，不暴露 token。蓝图不直接监听原始 SDK、不过滤真实/模拟身份、不决定付费权益，也不自行提交 ACK。C++ 校验后才发一次表现通知；蓝图可调颜色、时长和特效，不可改助力上限和概率公式。

蓝图绑定在 BeginPlay/初始化时进行，EndPlay/销毁时解绑，重开 PIE 不重复绑定。检查失效 Actor/组件引用，异步使用弱引用。不得在每帧全量扫描观众。现有资产优先复用，新蓝图先在独立目录创建；记录包路径、父类、输入输出和连接步骤，二进制资产只由一人编辑。

如果不具备编辑器资产写入工具，AI 必须给出可执行的节点步骤，由程序员保存并验证；不得谎报已生成 `.uasset`。一次极短护卫光效即可满足本周最小表现，不新增全屏界面。

## 4. 验证与证据

先运行现有相关用例，再为本次关键状态边界增加有意义的自动化测试。已有测试名包括 `BoundlessImmortality.LiveWeapons.AudienceCommands`、`AudienceRouting`、`AcknowledgementReconnect`；插件部分测试仍以 `GeometricWarfare.*` 命名，名称是历史来源，不代表本项目业务已经覆盖。

由本机 UE 安装确认 `<UE_ROOT>`，使用对应 `Build.bat` 构建 `BoundlessImmortalityEditor Win64 Development`，不要复制一个不存在的引擎路径。随后从编辑器 Session Frontend 的 Automation 面板运行上述用例及本次新增测试并导出报告。需要命令行运行时，先核对本机 UE 参数及退出/报告路径；本规范不把未执行命令写作已通过。

若修改 Python 本机服务，才额外运行：

```powershell
python -m unittest discover -s Tools/CultivationService/tests -v
```

该命令不证明 UE 或 SDK 正确。本周主线无需改 Python 服务。`Tools/InkFrontend/verify_ink_economy_pie.py` 会消耗/发放本地数据，运行前备份；无需为一条助力修补反复执行全套经济脚本。

验证等级必须单列：静态审查、C++ 编译、自动化、可渲染 PIE、打包运行、官方自测、真实测试直播、审核/上线。只完成其中某一层不得替代其他层。真实平台无条件时写明未测与缺失项。
